# ReComo | Запись — демо-бот для beauty-мастера

Демонстрационный Telegram-бот для записи к вымышленному мастеру по наращиванию
ресниц **ReComo** (Екатеринбург). Бот полностью рабочий: реальная запись,
расчёт свободных слотов, отмена/перенос, напоминания и админ-панель — всё
хранится в PostgreSQL.

## Стек

Python 3.12, aiogram 3, SQLAlchemy 2 (async), PostgreSQL, Alembic, APScheduler,
Docker Compose.

---

## 1. Создание бота через BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` и следуйте инструкциям (имя, username).
3. BotFather выдаст токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

## 2. Куда вставить `BOT_TOKEN`

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

И вставьте полученный токен в `BOT_TOKEN=`.

## 3. Как узнать свой Telegram ID администратора

Откройте [@userinfobot](https://t.me/userinfobot) и отправьте ему любое
сообщение — он пришлёт ваш числовой ID.

## 4. Заполнение `.env`

```env
BOT_TOKEN=токен_от_BotFather
DATABASE_URL=postgresql+asyncpg://postgres:postgres@db:5432/beauty_demo
ADMIN_IDS=ваш_telegram_id
TIMEZONE=Asia/Yekaterinburg
```

`ADMIN_IDS` можно указать несколько ID через запятую: `111,222`. Только эти
пользователи увидят кнопку «⚙️ Админ-панель» и смогут ей пользоваться.

`DATABASE_URL` менять не нужно, если вы запускаете через Docker Compose —
хост `db` соответствует имени сервиса в `docker-compose.yml`.

## 5. Запуск через Docker

```bash
docker compose up --build -d
```

Поднимутся два сервиса: `db` (PostgreSQL) и `bot`. Бот стартует не раньше,
чем PostgreSQL пройдёт healthcheck.

## 6. Применение миграций

```bash
docker compose run --rm bot alembic upgrade head
```

## 7. Загрузка демо-данных

```bash
docker compose run --rm bot python -m app.seed
```

После этого в базе появятся:

- 4 услуги (классика, 2D, 3D, ламинирование) с ценами и длительностью;
- график работы (Пн–Пт 10:00–19:00 с перерывом 14:00–15:00, Сб 11:00–16:00,
  Вс — выходной);
- профиль мастера (город, адрес, текст «О мастере», ссылка на карту);
- 3 демо-клиента с уже занятыми слотами («сегодня» и «завтра»), чтобы сразу
  было видно, что бот учитывает занятые слоты.

Скрипт идемпотентен — повторный запуск ничего не сломает (просто ничего не
сделает, если данные уже загружены).

## 8. Запуск бота

Если вы уже запустили `docker compose up --build -d`, бот уже работает —
просто напишите ему `/start` в Telegram. Логи:

```bash
docker compose logs -f bot
```

### Запуск без Docker (локально)

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
# поднимите свой PostgreSQL и укажите его в DATABASE_URL в .env
alembic upgrade head
python -m app.seed
python -m app.bot
```

## 9. Как добавить реальные фотографии в портфолио

Готовых фото в демо нет специально: Telegram выдаёт `file_id` только после
реальной отправки фото в чат с ботом, сгенерировать его заранее нельзя.
Зато в боте есть удобный механизм загрузки:

1. Напишите боту `/start` под администраторским аккаунтом (тем, чей ID указан
   в `ADMIN_IDS`).
2. `⚙️ Админ-панель` → `📸 Портфолио` → выберите категорию → `➕ Добавить фото`.
3. Отправьте фотографию в чат — бот сохранит её `file_id` в базу.
4. Добавьте подпись или нажмите «Пропустить подпись».

Фото сразу появится в разделе «📸 Портфолио» у всех клиентов. Удалить фото
можно там же кнопкой «🗑 Удалить фото №N».

## 10. Как изменить услуги и цены

Через админ-панель, без правки кода:

`⚙️ Админ-панель` → `💫 Услуги` → выберите услугу → `💰 Цена` / `⏱ Длительность` /
`✏️ Название` / `✏️ Описание` → введите новое значение.

Там же можно:

- добавить новую услугу (`➕ Добавить услугу`);
- временно отключить услугу, не удаляя её (`🚫 Отключить` / `✅ Включить`) —
  отключённая услуга не показывается клиентам, но остаётся в истории записей;
- удалить услугу совсем (`🗑 Удалить`) — доступно только если по ней ещё нет
  ни одной записи (иначе бот предложит отключить услугу вместо удаления).

### Изменение графика работы и разовые выходные

`⚙️ Админ-панель → 🕐 Расписание`:

- **✏️ Изменить график** — выбрать день недели и поменять часы работы,
  перерыв или сделать день выходным/рабочим.
- **📅 Особые дни** — разовый выходной на конкретную дату (праздник) или
  день с нестандартными часами, без изменения недельного графика.

**Как это работает с уже существующими записями.** Изменение графика
никогда не отменяет записи автоматически. Если новые часы конфликтуют с уже
подтверждённой записью (например, запись на 15:00, а мастер хочет начинать
день с 16:00), бот покажет список затронутых записей и попросит подтвердить
изменение явно:

```
⚠️ Пн: часы работы изменятся на 16:00–19:00.

На это время уже есть подтверждённые записи:
• 24 августа 15:00 — Анна — Классическое наращивание

Эти записи не будут отменены автоматически — при необходимости
отмените или перенесите их вручную через «📅 Записи».
Сохранить изменение графика всё равно?
```

После подтверждения график сохраняется, а запись остаётся активной как есть —
дальше мастер сам решает, отменять её или оставить. Новые слоты в это время
клиентам больше не предлагаются.

## Проверка полного сценария

**Клиент:**
`/start` → «💫 Услуги и запись» → карточка услуги → «📅 Записаться на эту
услугу» → выбор даты → выбор свободного времени → «✅ Подтвердить» →
получает подтверждение записи.

**Мастер:**
«⚙️ Админ-панель» → «📅 Записи» → «Сегодня»/«Завтра»/«Ближайшие записи» →
открыть запись и увидеть клиента → «💫 Услуги» → изменить цену → «🕐 Расписание»
→ «📸 Портфолио» → загрузить фото.

**Отмена:** «📋 Моя запись» → «❌ Отменить» → подтвердить — слот снова
свободен для записи.

**Перенос:** «📋 Моя запись» → «🔄 Перенести» → новая дата/время →
подтвердить — старый слот освобождается только после подтверждения нового,
новый слот занят.

**Тестовое напоминание:** «⚙️ Админ-панель» → «🧪 Тестовое напоминание» —
администратору сразу приходят примеры напоминаний за 24 часа и за 2 часа, не
дожидаясь реального времени.

## Тесты

Тесты используют реальный PostgreSQL (без SQLite), таблицы создаются и
дропаются перед каждым тестом. Для импорта `app.config` нужен `.env` (или
переменные окружения) — используйте свои значения либо тестовые заглушки:

```bash
cp .env.example .env   # если ещё не создавали; BOT_TOKEN может быть фиктивным
export TEST_DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/beauty_demo_test
pytest -v
```

`TEST_DATABASE_URL` должен указывать на отдельную базу (не ту, что в `.env`),
чтобы тесты могли безопасно дропать и пересоздавать таблицы.

Покрыты: генерация слотов (шаг 30 минут, обеденный перерыв, конец рабочего
дня, выходной день, суббота с укороченным графиком), создание записи,
пересечение записей, отмена, перенос (включая освобождение старого и запрет
переноса на уже занятое время).

## Структура проекта

```
app/
  models/        SQLAlchemy-модели (User, Service, Appointment, WorkingSchedule,
                 ScheduleException, PortfolioItem, BusinessProfile)
  repositories/  Доступ к БД
  services/      Бизнес-логика (расчёт слотов, бронирование, напоминания)
  keyboards/     Инлайн-клавиатуры
  callbacks/     Типизированные callback_data (aiogram CallbackData)
  states/        FSM-состояния админки
  handlers/      Роутеры aiogram — client/ и admin/
  middlewares/   DB-сессия на каждый апдейт
  scheduler/     APScheduler — джоба напоминаний
  seed.py        Наполнение демо-данными
alembic/         Миграции
tests/           pytest
```

добавить это позже без переписывания.
